### 🔴 [2] CRITICAL — BROKEN-ACCESS-CONTROL tại `app/oauth/service.py:217`

**Mô tả ngắn:** Đăng nhập Google nhận **bất kỳ** access token nào của Google, chỉ gọi endpoint `userinfo` rồi tìm user theo email. Không kiểm tra token có được cấp cho FundLok hay không (không check `aud`/`azp`), cũng không check `email_verified`.

**Tại sao nguy hiểm?**

Access token Google không gắn với một ứng dụng cụ thể khi dùng với `userinfo`. Nếu nạn nhân từng bấm "Đăng nhập bằng Google" ở **bất kỳ** website nào do kẻ tấn công kiểm soát (hoặc một app bên thứ ba bị lộ token), token đó có thể được đem sang FundLok và đổi lấy **phiên đăng nhập đầy đủ** vào tài khoản của nạn nhân. Điều này áp dụng cả cho tài khoản mật khẩu (liên kết theo email) và tài khoản đã bật TOTP (xem [5]). Trên một sàn cho vay, đó là quyền xem hồ sơ KYC, dữ liệu tài chính và thao tác tiền của nạn nhân.

**Hacker khai thác như thế nào?**

1. Kẻ tấn công dựng một trang có nút "Sign in with Google" (client ID của chính họ).
2. Nạn nhân đăng nhập → kẻ tấn công nhận được access token Google của nạn nhân.
3. Gửi `POST /auth/oauth/login {"provider":"google","access_token":"<token của nạn nhân>"}` tới FundLok.
4. `userinfo` trả về email nạn nhân → `get_or_create_user` tìm user theo email → FundLok phát access + refresh token cho kẻ tấn công.

**Code hiện tại (NGUY HIỂM)**

```python
def verify_token(self, token: str) -> dict:
    return self.verify_access_token(token)          # bỏ qua đường kiểm tra ID token có check aud
def verify_access_token(self, access_token: str) -> dict:
    url = "https://www.googleapis.com/oauth2/v3/userinfo"
    with httpx.Client(timeout=10.0) as client:
        response = client.get(url, headers={"Authorization": f"Bearer {access_token}"})  # dòng 217: không check aud/azp
    claims = response.json()
    if not claims.get("sub") or not claims.get("email"):   # không check email_verified
```

**Code an toàn (sửa thành)**

```python
def verify_token(self, token: str) -> dict:
    # Chỉ nhận Google ID token; verify_id_token đã kiểm chữ ký, aud == GOOGLE_CLIENT_ID, iss, exp
    claims = self.verify_id_token(token)
    if claims.get("email_verified") is not True:
        raise HTTPException(status_code=401, detail="Google email is not verified")
    return claims
# Nếu buộc phải nhận access token: gọi https://oauth2.googleapis.com/tokeninfo?access_token=...
# và từ chối nếu aud/azp != settings.GOOGLE_CLIENT_ID.
# Lưu provider `sub` cho mỗi user và so khớp theo sub ở các lần đăng nhập sau.
```

Frontend cần gửi ID token (credential của Google Identity Services) thay cho access token.

## ĐÃ ĐẠT

- ✓ SQL-INJECTION — Chỉ dùng SQLAlchemy với tham số ràng buộc; SQL trong migration là chuỗi tĩnh
- ✓ SLOPSQUATTING — Mọi package import đều là package thật
- ✓ MASS-ASSIGNMENT — Schema khai báo rõ từng field; không có đường nâng quyền qua body
- ✓ INSECURE-DESERIALIZATION — Chỉ `json.loads`/`yaml.safe_load`; XML dùng ElementTree (không resolve entity ngoài)
- ✓ SSRF — URL gọi ra ngoài đến từ cấu hình/discovery, không từ input người dùng
- ✓ PATH-TRAVERSAL — Tên entry trong zip không dùng làm đường dẫn; key R2 do server tạo
- ✓ CSRF — Cookie HttpOnly + SameSite=Lax, body JSON; phần lớn dùng Bearer
- ✓ WEAK-PASSWORD-HASHING — Argon2 cho mật khẩu và recovery code; webhook Didit dùng HMAC-SHA256 + `compare_digest`
- ✓ JWT-NONE-ALGORITHM — Mọi `decode` cố định thuật toán; token có `purpose` bị từ chối làm phiên
- ✓ CORS-MISCONFIG — Danh sách origin cụ thể, không có `*`
- ✓ COMMAND-INJECTION — Không có shell với input người dùng; CI không chèn `github.event.*` vào `run`
